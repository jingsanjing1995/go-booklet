# 01 · 认识 Go

这一章不写长代码，先把语言的轮廓画清楚：它从哪来、长什么样、和常见语言差在哪。有了轮廓，后面的语法才不会变成孤立的规则清单。

---

## 1. 一张时间线

| 年份 | 事件 | 对你意味着什么 |
|------|------|----------------|
| 2009 | 公开发布 | 设计目标就是编译快、并发简单、语法少 |
| 2012 | Go 1 兼容承诺 | 旧代码几乎一直能编，生态稳定 |
| 2018 | modules 成为默认方向 | 不再依赖 GOPATH 放代码 |
| 2022 | Go 1.18 泛型 | 容器、算法不必再靠 `interface{}` |
| 2023+ | 工具与运行时持续迭代 | `log/slog`、PGO、更稳的 GC 与调度 |

兼容承诺很重要：你在小册里学的大部分写法，五年后仍然成立。语言进化偏向「加小功能、不破坏旧代码」。

## 2. 语言画像（用代码感受）

下面这段把「包、函数、错误、切片、goroutine」挤在一个最小程序里。先建立画面，细节后面拆。

```go
package main

import (
	"fmt"
	"time"
)

func greet(name string) (string, error) {
	if name == "" {
		return "", fmt.Errorf("name is empty")
	}
	return "hello, " + name, nil
}

func main() {
	msg, err := greet("Go")
	if err != nil {
		fmt.Println("失败:", err)
		return
	}
	fmt.Println(msg)

	done := make(chan string)
	go func() {
		time.Sleep(50 * time.Millisecond)
		done <- "goroutine 说：我跑完了"
	}()
	fmt.Println(<-done)
}
```

读这段时抓住四点：

1. **入口是 `package main` + `func main`**，没有类、没有 `public static void`。
2. **函数可以多返回值**，最后一个常常是 `error`。
3. **失败是值**，调用方必须看 `err`。
4. **`go f()` 就能并发**，用 channel 把结果送回来。

## 3. 和常见语言对照

| 话题 | Java / C# | Python | Go |
|------|-----------|--------|-----|
| 面向对象 | 类、继承、虚方法 | 类 + 鸭子类型 | 结构体 + 接口，没有继承树 |
| 错误 | 异常 | 异常 | `error` 值；panic 留给真正的崩溃 |
| 泛型 | 成熟 | 运行期动态 | 1.18 起有，约束用接口 |
| 并发 | 线程 / async | GIL + asyncio / 多进程 | goroutine + channel |
| 部署 | JVM / 运行时 | 解释器 + 依赖 | 静态二进制 |
| 空值 | `null` 到处都是 | `None` | 指针/`interface`/`slice`/`map`/`chan` 可为 nil，规则不同 |

最容易踩坑的对照：

- **没有隐式数值转换**：`int` 和 `int64` 是不同类型，必须显式转换。
- **没有泛型方法那种「类上的 T」**（到目前为止），泛型主要在函数和类型定义上。
- **没有枚举关键字**，用 `const + iota` 模拟。
- **没有 while / do-while**，一律 `for`。
- **没有三元运算符**，用 `if` 写清楚。

## 4. 编译模型：你最终交出的是一个文件

```text
.go 源文件
   │  go build
   ▼
单个可执行文件（默认静态链接）
   │  拷到 Linux / 设好 GOOS/GOARCH
   ▼
目标机器直接跑，不必装 Go
```

交叉编译几乎是一句话：

```bash
GOOS=linux GOARCH=amd64 go build -o app ./cmd/app
```

这对 CLI 和服务器都极友好：CI 产出二进制，目标环境没有「再装一遍运行时」的故事。

## 5. 并发为什么被称作一等公民

在很多语言里，「同时做两件事」要么创建操作系统线程（贵），要么上 async 染色（`async/await` 传染）。Go 的选择是：

- 用户代码写 `go doWork()`；
- 运行时把成千上万个 goroutine 调度到少量 OS 线程上（GMP 模型，高级篇再展开）；
- 阻塞在 channel、网络、锁上时，调度器可以去跑别的 goroutine。

所以 Go 服务里「一个连接一个 goroutine」是常见、也通常合理的写法。前提是你要会取消、超时和收口，否则会泄漏。这些是第三篇的主题。

## 6. 标准库的分量

学 Go 的前几周，优先把标准库摸熟，而不是先上框架：

| 包 | 用途 |
|----|------|
| `fmt` / `log` / `log/slog` | 打印与结构化日志 |
| `errors` / `fmt.Errorf` | 错误构造与包装 |
| `strconv` / `strings` / `bytes` / `unicode/utf8` | 文本与转换 |
| `io` / `os` / `bufio` / `encoding/json` | IO 与编码 |
| `net/http` | HTTP 客户端和服务端已经能用 |
| `context` | 超时、取消、请求级值 |
| `sync` / `sync/atomic` | 共享内存同步 |
| `testing` | 测试、基准、Fuzz |

很多生产服务只用标准库 + 少量领域库（驱动、观测）。框架不是必须的。

## 7. 兼容性与「少即是多」的代价

Go 1 兼容承诺让升级编译器通常很轻松。代价是：一些「大家都想要」的功能来得很晚（泛型），有些则一直没有（默认参数、异常、传统枚举）。

小册的立场是：**先把现有武器用熟**。你会发现缺的语法，常常能用小函数、小接口和代码生成补上，而且团队更容易读。
