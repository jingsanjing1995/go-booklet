# 03 · 程序结构与第一个程序

Go 程序的骨架非常固定：包、导入、声明。把骨架记牢，后面加类型和方法都只是往骨架上挂肉。

---

## 1. 最小程序

```go
package main

import "fmt"

func main() {
	fmt.Println("hello, 小册")
}
```

规则：

- 可执行程序必须是 `package main`，并且有 `func main()`。
- `main` **没有参数、没有返回值**。命令行参数走 `os.Args` 或 `flag`。
- 退出码：正常落到函数末尾是 0；要非 0 用 `os.Exit(n)`，但 `os.Exit` **不会跑 defer**。

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	if len(os.Args) < 2 {
		fmt.Fprintln(os.Stderr, "用法: hello <名字>")
		os.Exit(2)
	}
	fmt.Println("hello,", os.Args[1])
}
```

`os.Args[0]` 是程序路径本身，用户参数从 `[1]` 开始。

## 2. 文件、包、导入

一个目录 = 一个包。同目录所有 `.go` 文件的 `package` 名必须相同（测试文件可以是 `foo_test`）。

```text
greet/
  greet.go      // package greet
  format.go     // package greet
  greet_test.go // package greet  或 package greet_test
```

导入：

```go
import (
	"fmt"                            // 标准库
	"example.com/hello/internal/greet" // 本模块
	ali "encoding/json"              // 别名
	_ "net/http/pprof"               // 只为副作用（注册路由）
)
```

- 未使用的 import 是**编译错误**，不是警告。`goimports` 会自动加删。
- `.` 导入（`import . "fmt"`）会污染名字空间，库代码里不要用。
- `_` 导入只执行目标包的 `init`。

包名不必等于目录名，但**强烈建议一致**，且短、小写、不用下划线。引用时用的是包名：`fmt.Println`，不是路径最后一段的「感觉」。

## 3. 声明顺序与可见性

文件大致可以看成：

```go
package foo

import "fmt"

const Version = "v1" // 导出

var defaultName = "gopher" // 未导出

type User struct { // 导出类型
	Name string // 导出字段
	id   int    // 未导出字段
}

func New(name string) User { // 导出函数，常作构造
	return User{Name: name}
}

func (u User) greet() string { // 未导出方法
	return "hi, " + u.Name
}
```

**首字母大写 = 对其他包可见（导出）**。这是唯一的可见性开关，没有 `public/private` 关键字。同包内大小写都能互相访问。

## 4. init 函数：能不用就不用

每个文件可以有一个或多个 `init()`，无参数无返回值，不能被手动调用。初始化顺序：

1. 导入的包先初始化（依赖图，不能有环）。
2. 当前包的包级变量按依赖关系初始化。
3. 各文件的 `init` 按编译器处理的文件顺序执行。
4. 最后才进 `main`。

```go
var started time.Time

func init() {
	started = time.Now()
}
```

`init` 难测试、难发现、执行顺序不直观。注册、读配置、连数据库，优先放到 `main` 或显式的 `New/Start` 里。`_ "driver"` 这种驱动注册是少数合理用途。

## 5. 注释就是文档

```go
// Package greet 提供一句问候。
package greet

// Hello 返回对 name 的问候。
// name 为空时返回错误。
func Hello(name string) (string, error) {
	// 实现注释用普通双斜杠即可
	if name == "" {
		return "", fmt.Errorf("name is empty")
	}
	return "hello, " + name, nil
}
```

- 包注释：`// Package xxx ...`，放在 `package` 子句上方。
- 导出符号的注释必须以符号名开头：`// Hello 返回...`。
- `go doc` 和 pkg.go.dev 都靠这些注释。

块注释 `/* ... */` 多用于临时关掉一大段，正式文档更常用行注释。

## 6. 一个稍完整的「第一个程序」

把参数、错误、退出码放在一起：

```go
package main

import (
	"errors"
	"fmt"
	"os"
	"strings"
)

func hello(name string) (string, error) {
	name = strings.TrimSpace(name)
	if name == "" {
		return "", errors.New("名字不能为空")
	}
	return "你好，" + name, nil
}

func main() {
	if len(os.Args) < 2 {
		fmt.Fprintln(os.Stderr, "用法: hello <名字>")
		os.Exit(2)
	}
	msg, err := hello(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, "错误:", err)
		os.Exit(1)
	}
	fmt.Println(msg)
}
```

对应示例：`codes/01-hello`。

## 7. 编译单元里还有什么

- `*_test.go` 默认不进入普通 `go build`，只给 `go test` 用。
- 构建标签（constraint）：

```go
//go:build linux

package osinfo
```

文件只在 Linux 上参与编译。旧语法是 `// +build linux`，现在用 `//go:build`。

- `go:generate` 在注释里挂代码生成命令，`go generate ./...` 时执行。入门先知道有这个钩子。
