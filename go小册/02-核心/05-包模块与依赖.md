# 05 · 包、模块与依赖

语法会了之后，项目靠包来切边界。模块（module）解决「版本和下载」；包（package）解决「名字和可见性」。两者叠在一起，才是日常的 `go.mod` 生活。

---

## 1. 包：编译和命名的单位

- 一个目录一个包，包名通常等于目录名。
- 导入路径是 **模块路径 + 目录**，不是包名。引用时用包名。

```go
import "example.com/shop/internal/user"

u, err := user.Find(ctx, id) // 用的是 package user
```

好包名：短、小写、不用 `util`/`common`/`base` 当垃圾桶。`user` 比 `userServiceUtil` 好。

循环导入是编译错误。出现 `a → b → a` 时，说明抽象切错了：把共享类型下沉到第三包，或用接口把依赖方向倒过来。

---

## 2. 导出规则再强调一遍

| 名字 | 谁能看 |
|------|--------|
| `User` `New` `ErrNotFound` | 其他包 |
| `user` `newInternal` | 仅本包 |

同包跨文件可以直接用未导出符号。所以「一个包拆很多文件」完全正常；「为了访问未导出字段把测试写成 `package user`」也常见。

外部测试包 `package user_test` 只能看到导出 API，更像真实用户，适合测公开行为。

---

## 3. 模块：版本的边界

```text
module example.com/shop

go 1.22

require (
    github.com/jackc/pgx/v5 v5.6.0
)
```

语义版本：`v1.2.3`。**v0 不保证兼容**；v1 起，破坏性变更应该升到 v2，并且**导入路径带 `/v2`**：

```go
import "github.com/foo/bar/v2"
```

这是 Go 的「导入路径含主版本」规则，避免一个程序里悄悄混用不兼容的 v1/v2 却同名。

常用命令：

```bash
go get example.com/lib@v1.4.2
go get example.com/lib@latest
go get example.com/lib@none          # 删除
go mod tidy
go mod why example.com/lib
go list -m -u all                    # 看可升级
go get -u ./...                      # 谨慎：会升一堆
```

`replace` 只给本地调试：

```go
replace example.com/lib => ../lib
```

不要把临时 replace 提交到库的发布版本里坑下游。

## 4. internal 与 testdata

```text
shop/
  go.mod
  cmd/shop/main.go
  internal/user/...
  internal/order/...
  testdata/golden.json
```

- `internal` 下的包，只有位于 `internal` 父树内的代码能导入。`example.com/other` 导入 `example.com/shop/internal/user` 会编译失败。
- `testdata` 目录默认不参与编译，放测试夹具正好。

公开库尽量小导出面：能藏进 `internal` 就藏。

## 5. 依赖选择

优先顺序：

1. 标准库
2. `golang.org/x/...`（官方扩展，质量接近标准库）
3. 领域里被广泛使用、有版本政策的库
4. 自己写

引入前看：许可证、最近提交、issue 处理、是否 module-aware、API 是否稳定、会不会把巨大依赖树拖进来（`go list -m all`）。

**不要**随便关掉 `GOSUMDB`。校验失败说明下载内容对不上，应排查网络/镜像，而不是闭眼跳过。

## 6. 构建标签与多平台文件

```go
//go:build linux && !android

package disk

func total() (uint64, error) { /* linux 实现 */ }
```

```go
//go:build darwin

package disk

func total() (uint64, error) { /* darwin 实现 */ }
```

同包同名函数靠标签互斥。文件名习惯：`stat_linux.go`、`stat_darwin.go`。

`*_windows.go` 这种后缀是约定，真正生效的是 build tag 或 GOOS 文件名规则（`foo_linux.go` 仅 Linux 编译）。

---

## 7. 可执行入口与库不要混在一个包

库包（`package user`）不该有 `func main`。入口放 `cmd/xxx`。这样别人 `import` 你的库时，不会把 CLI 逻辑也拉进来，测试也更干净。

一个模块多个命令：

```text
cmd/shopd/main.go
cmd/shopctl/main.go
```

## 8. 最小工作流（请实际做一遍）

```bash
mkdir shop && cd shop
go mod init example.com/shop
mkdir -p cmd/shop internal/greet
# 写代码
go run ./cmd/shop
go test ./...
go mod tidy
```
