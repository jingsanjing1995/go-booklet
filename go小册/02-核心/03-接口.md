# 03 · 接口

接口是 Go 里的多态。关键设计：**由实现方默默满足，而不由定义方事先登记**。一个类型只要方法集对上，它就实现了该接口。

---

## 1. 最小接口

```go
type Namer interface {
	Name() string
}

type User struct{ name string }

func (u User) Name() string { return u.name }

func greet(n Namer) string {
	return "hello, " + n.Name()
}
```

`User` 没有写 `implements Namer`。这让标准库可以定义 `io.Reader`，全世界的类型事后都能适配。

习惯：接口由**使用方**定义，而且尽量小。

```go
// 好：调用方只需要 Read
func slurp(r io.Reader) ([]byte, error) {
	return io.ReadAll(r)
}
```

---

## 2. 方法集：值和指针到底实现了谁

| 类型 | 方法集包含 |
|------|------------|
| `T` | 所有 `func (T)` 方法 |
| `*T` | 所有 `func (T)` **和** `func (*T)` 方法 |

因此：

```go
func (u *User) Rename(s string) { u.name = s }

var n Namer
n = User{}   // 若 Namer 只要 Name()（值接收者），可以
// n = User{} 若还要 Rename（指针接收者），不行
n = &User{}  // *User 两种方法都有
```

规则记成一句话：**接口里如果有指针接收者方法，装进去的动态值必须是指针。**

---

## 3. 空接口与 any

`interface{}` 的别名是 `any`（1.18+）。它没有方法，所以任何值都满足。

```go
var v any
v = 1
v = "s"
v = User{}
```

失去的是编译期类型信息，换来的是运行期断言。能用泛型或具体类型就不要用 `any`。

---

## 4. 类型断言与类型 switch

```go
func describe(v any) {
	s, ok := v.(string)
	if !ok {
		fmt.Println("not string")
		return
	}
	fmt.Println(s)
}

func describe2(v any) {
	switch x := v.(type) {
	case nil:
		fmt.Println("nil")
	case string:
		fmt.Println("str", x)
	case int:
		fmt.Println("int", x)
	case Namer:
		fmt.Println("namer", x.Name())
	default:
		fmt.Printf("other %T\n", v)
	}
}
```

单值断言 `v.(string)` 失败会 **panic**。能用 comma-ok 就用 comma-ok。

## 5. 接口的内部是两个字

接口值可以想成 `(动态类型, 动态值)`。这解释了最著名的坑：

```go
var err error          // (nil, nil) —— 接口本身是 nil
var p *os.PathError = nil
err = p                // ( *os.PathError, nil ) —— 接口不是 nil！
if err != nil {
	fmt.Println("看起来有错") // 会进来
}
```

**永远不要用「具体 nil 指针」赋给接口再和 nil 比较。** 函数里应返回：

```go
func load() error {
	err := do()
	if err != nil {
		return err
	}
	return nil // 不要 return 一个类型确定的 nil 指针
}
```

`(类型, nil 值)` 的接口可以调方法（走到具体类型的 nil 接收者）。`(nil, nil)` 调方法会 panic。

---

## 6. 组合接口

```go
type ReadCloser interface {
	io.Reader
	io.Closer
}
```

标准库的 `io.ReadWriteCloser` 就是这样拼的。小接口组合优于一个 20 个方法的大接口。

常见标准接口，请当单词背：

| 接口 | 方法 |
|------|------|
| `io.Reader` | `Read([]byte) (int, error)` |
| `io.Writer` | `Write([]byte) (int, error)` |
| `io.Closer` | `Close() error` |
| `fmt.Stringer` | `String() string` |
| `error` | `Error() string` |
| `json.Marshaler` | `MarshalJSON() ([]byte, error)` |

实现 `String()` 能让 `%v`/`%s` 更好看；实现 `error` 就能当错误传。

## 7. 适配与「用函数实现接口」

```go
type HandlerFunc func(http.ResponseWriter, *http.Request)

func (f HandlerFunc) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	f(w, r)
}
```

普通函数套一层就能进 `http.Handler`。自己写库时这也是友好 API 的套路。

断言「一定实现了某接口」，用编译期检查：

```go
var _ http.Handler = (*MyHandler)(nil)
var _ io.Reader = ReaderFunc(nil)
```

编不过立刻发现，比运行时才炸好。

---

## 8. 接口不要过早

反模式：每个结构体先配一个接口，再只被一个实现满足。这没有带来可测性（测试可以直接用真结构体或小函数），只多了一层跳转。

更好的时机：

- 有 2+ 种实现，或标准库已有接口（`io.Reader`）
- 需要在测试里替换（时钟、网络、存储）
- 包之间要解耦，且方法集已经稳定

接口定义在**调用方包**里，实现方甚至不用 import 调用方。这叫「依赖倒置的 Go 式写法」。
