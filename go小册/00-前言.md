# 00 · 前言：Go 的味道与这份小册的约定

Go 不是「更好的 Java」，也不是「更快的 Python」。它是一门为**工程协作**和**网络服务**长出来的语言：语法少、工具齐、并发是一等公民、编译快、部署简单。

读完前言，你应该能回答三件事：

1. 为什么很多人用 Go 写后端、云原生和 CLI？
2. 学 Go 时哪些「其他语言习惯」要先放下？
3. 这份小册各篇分别解决什么问题？

---

## 1. Go 在解决什么问题

2007 年前后，Google 内部的 C++ 构建慢、Java 太重、脚本语言难扛大规模服务。Go 的设计目标很明确：

- **编译快**：大仓库也能秒级反馈。
- **读起来简单**：新人能在一周内读懂同事的代码。
- **天然并发**：用 goroutine / channel 描述「同时做几件事」，而不是先学线程池。
- **部署简单**：静态链接，一个二进制就能跑。

今天它常见于：

| 场景 | 例子 | 为什么合适 |
|------|------|------------|
| HTTP / RPC 服务 | API、网关、微服务 | 标准库够用，并发模型贴合 I/O |
| 云原生基础设施 | Docker、K8s、etcd、Prometheus | 部署简单，长期可维护 |
| CLI 与开发工具 | `gh`、`hugo`、各类内部工具 | 单文件分发，交叉编译方便 |
| 数据管道 / 代理 | 日志采集、反向代理 | 高并发连接，内存可控 |

它不擅长的事也要心里有数：重 GUI、数值计算生态、强依赖泛型元编程的领域，Go 不是第一选择。

## 2. 先建立「Go 味道」

学语法之前，先记住几条会反复出现的味道。后面每章都在强化它们。

### 2.1 少即是多

没有 class 继承树，没有隐式转换狂欢，没有宏。类型少、关键字少、一种循环（`for`）。复杂需求用**组合**和**接口**拼出来，而不是再发明一套语法。

### 2.2 显式好过巧妙

错误是值，要当面处理。没有 try/catch 把控制流藏起来。`if err != nil` 看起来啰嗦，换来的是调用链上错误不会悄无声息地消失。

### 2.3 组合优于继承

结构体可以嵌套（embedding），接口可以很小（一个方法也行）。「一个类型实现多个小接口」比「一个大基类往下传」更常见。

### 2.4 并发用通信来同步

口号是：*Don't communicate by sharing memory; share memory by communicating.*  
优先用 channel 传递所有权；必须共享内存时，再用 `sync.Mutex` 等原语，并且把锁的范围缩到最小。

### 2.5 工具链是语言的一部分

`go fmt`、`go test`、`go mod`、`go vet`、race detector 不是插件，是默认工作方式。格式之争在仓库里不应该存在。

## 3. 这份小册怎么组织

| 篇 | 你将获得 | 读完能做什么 |
|----|----------|--------------|
| 入门 | 类型、控制流、函数、切片/Map、字符串 | 写命令行小工具、读懂简单源码 |
| 核心 | 指针、方法、接口、错误、模块、标准库 | 组织多文件项目，正确处理失败 |

每章结构尽量统一：

1. **这一章解决什么**
2. **最小例子**（能跑）
3. **规则与易错点**
4. **和真实代码的对应**
5. **想一想 / 练习**

## 4. 代码约定

- 包名短、小写、不用下划线：`httputil`，不是 `http_util`。
- 导出用大写：`User`、`NewClient`；未导出用小写。
- 错误变量以 `Err` 开头：`var ErrNotFound = errors.New("not found")`。
- 接口名常常是方法名加 `er`：`Reader`、`Closer`。能一个方法就一个方法。
- 示例默认 `package main`，方便 `go run`；讲库设计时会改成 `package user`。

零值有意义，这是 Go 里很重要的一句话：

```go
var s []int          // nil 切片，len=0，可以直接 range / append
var m map[string]int // nil map，读是安全的，写会 panic
var buf bytes.Buffer // 零值就能用，不必 New
```

学任何类型时都问一句：**它的零值是什么？零值能不能直接用？**

## 5. 学习时请放下的习惯

| 来自 | 请改成 |
|------|--------|
| 用 class + 继承建模一切 | 结构体 + 小接口 + 嵌入 |
| 用异常做普通错误 | 返回 `error`，只在真正不可恢复时 panic |
| 随便 new 线程 | `go f()`，再用 channel / WaitGroup 收口 |
| 追求「一行写完」 | 清晰的 `if` / 提前返回 |
| 自己发明项目骨架 | 先看标准库和常见仓库的扁平结构 |
