# 05 · 设计模式与常见陷阱

Go 里的「模式」通常是小函数、小接口、几个约定，而不是类图。这一章收两份清单：值得反复用的写法，以及值得反复避开的坑。当作全书索引来翻。

---

## 1. 常用写法

### 1.1 函数选项

```go
type Option func(*Server)

func WithAddr(a string) Option { return func(s *Server) { s.addr = a } }

func NewServer(opts ...Option) *Server {
	s := &Server{addr: ":8080"}
	for _, opt := range opts {
		opt(s)
	}
	return s
}
```

适合可选配置多、还要保持零值可用。配置很少时，直接结构体更清楚。

### 1.2 装饰器 / 中间件

`http.Handler` 套娃、`io.Reader` 外包一层限速或计数。嵌入接口 + 额外字段。

### 1.3 适配器

`http.HandlerFunc`：函数实现接口。自己也可以 `type VisitorFunc func(Node)`。

### 1.4 策略与小接口

```go
type Hasher interface{ Sum([]byte) []byte }
```

调用方定义接口，测试塞假实现。不要先画 20 个方法的 `IUserService`。

### 1.5 扇入扇出、工人池、errgroup

见并发篇。这是 Go 的「行为模式」。

### 1.6 Must 与包装

初始化用 `Must`；请求路径返回 `error`。库导出 `Parse` + `MustParse`。

### 1.7 函数式的一小撮

`Filter`/`Map` 用泛型写工具可以，但不要把业务写成无法打断点的链式回调。Go 偏好直来直去的 `for`。

经典 GoF 里依赖继承、运行时换实现的那部分，用嵌入 + 接口就够；单例用 `sync.Once`，不要自己搞双重检查锁。

## 2. 陷阱速查（按杀伤力）

| # | 坑 | 症状 | 处理 |
|---|----|------|------|
| 1 | typed-nil 接口 | `err != nil` 却没错误 | 只 `return nil` |
| 2 | 切片共享底层数组 | 改 A 动到 B | `clone` / 三下标 |
| 3 | `append` 没接回 | 调用方长度不变 | `s = append(s, x)` |
| 4 | nil map 写入 | panic | `make` |
| 5 | map 并发 | fatal / race | 锁或分片 |
| 6 | 字符串按下标当「字」 | 切坏中文 | `range` / `utf8` |
| 7 | `string(65)` | 得到 `"A"` | `strconv` |
| 8 | `:=` 阴影 | 外层 err 仍 nil | 注意作用域 |
| 9 | `defer` 在循环 | 文件句柄爆 | 包一层函数 |
| 10 | `os.Exit` 跳过 defer | 资源没关 | 先清理再 Exit |
| 11 | 忘记 `cancel()` | timer / G 泄漏 | `defer cancel()` |
| 12 | 忘记 `Body.Close` | 连接泄漏 | defer Close |
| 13 | `DefaultClient` 无超时 |  goroutine 挂死 | 自建 Client |
| 14 | 向已关 channel 发 | panic | 发送方关闭 |
| 15 | 重复 close / Unlock | panic | 所有权单一 |
| 16 | range 改副本 | 结构体没改掉 | 用下标 |
| 17 | JSON nil 切片变 `null` | 前端崩 | 初始化 `[]T{}` |
| 18 | 浮点当钱 | 一分钱对不上 | `int64` 分 |
| 19 | 用字符串判断错误 | 改文案即挂 | `errors.Is/As` |
| 20 | 测试靠 Sleep | 闪烁 | channel / WG |
| 21 | 复制 Mutex | 锁失效、vet 报 | 指针 |
| 22 | 锁内做 I/O | 吞吐塌 | 拷出再调 |
| 23 | 无限 `go` | 打爆下游 | 工人池 |
| 24 | 热路径反射 / `fmt` | 分配爆炸 | 生成代码、strconv |
| 25 | unsafe 省一次拷贝 | 随机崩 | 别省 |

## 3. 评审时可以问的问题

1. 错误链能不能 `Is`/`As`？有没有把上下文丢掉？
2. 每个 goroutine 的退出条件？
3. context 是否从入口传到 I/O？
4. 导出的东西是否都愿意当 API 养三年？
5. 测试失败时，名字和日志能不能定位到表里的哪一行？
6. 有没有 `-race`？
7. 新依赖值不值（体积、许可证、活跃度）？

---

## 4. 面试可以怎么答（短版）

- **切片**：ptr/len/cap，append 可能换数组。
- **接口 nil**：看 itab 不是看 data。
- **GMP**：G 代码、M 线程、P 队列；syscall 会移交 P。
- **channel vs mutex**：传递用 channel，共享小状态用锁。
- **GC**：并发三色，GOGC / GOMEMLIMIT。
- **逃逸**：返回指针、接口装箱、闭包。
- **错误**：值、包装、`%w`、不 panic。

答完用一两行代码佐证，比背名词强。

## 5. 读完小册之后

按这个顺序继续长肉：

1. 把 `codes/` 全部跑通，改坏再改回来。
2. 用小册骨架写一个带测试的 HTTP 服务。
3. 读 `io`、`net/http`、`context` 源码，对照 GMP/接口章。
4. 给自己的服务接 pprof，看一次真实画像。
5. 翻 Effective Go 和 Code Review Comments，当风格圣经。

Go 的高级不在于语法花活，而在于：**在约束很少的语言里，依然写出边界清楚、失败可见、并发可取消的程序。**
