# 04 · 接口底层

核心篇把接口当成「方法集合 + 动态派发」。这里补上运行时表示，专门解释两件事：

1. 为什么 `(*T)(nil)` 赋给 `error` 后不是 nil？
2. 接口调用和具体类型调用差在哪？装箱又是什么？

---

## 1. 两个字：类型 + 数据

一个接口值可以想成：

```text
iface {
    tab  *itab      // 动态类型信息 + 方法表
    data unsafe.Pointer
}
```

空接口 `any` 稍有不同（`eFace`：`_type` + `data`），因为没有方法表要填。有方法的接口才需要 **itab**。

- `tab == nil && data == nil` → 接口是 **nil**。`err == nil` 为真。
- `tab != nil && data == nil` → 动态类型在，值是 nil 指针。`err == nil` 为假。

```go
var p *MyError = nil
var err error = p
// err.tab 指向 (*MyError, error) 的 itab
// err.data == nil
```

这就是那道经典题的内存解释。

---

## 2. itab：一对类型只算一次

`itab` 缓存「具体类型 T 实现接口 I」的方法地址。第一次把 `T` 赋给 `I` 时，运行时会：

1. 检查 T 的方法集是否覆盖 I（编译期其实已经保证，运行时做组装）。
2. 填好方法槽。
3. 缓存起来，以后赋值复用。

所以「接口调用」= 读 itab 槽 + 间接跳转，通常就多一次跳转和失去部分内联。热到极致时，用具体类型或泛型会更快；日常这点开销换来的解耦非常值。

---

## 3. 装箱（boxing）

```go
var n int = 3
var v any = n
```

`n` 是栈上的字；赋给 `any` 时，运行时在**堆上复制一份**（小整数有时有特殊优化，但模型上按「可能分配」想），`data` 指向副本。改 `n` 不影响 `v`。

结构体赋给接口同样拷贝到堆（或已在堆上则取址）。这就是逃逸分析里「赋给接口 → 逃逸」的来源。

取出：

```go
n2 := v.(int) // 检查 tab 是否是 int，再拷回来
```

失败的类型断言：comma-ok 返回零值+false；单值形式 panic。

---

## 4. 比较

接口可以 `==`，当且仅当：

- 都是 nil 接口，或
- 动态类型相同，且动态值可比较并且相等。

动态值是切片、map、函数 → 比较会 **panic**。`any` 装了切片再当 map 键或 `==`，运行时炸弹。

```go
var a any = []int{1}
var b any = []int{1}
// a == b  // panic
```

---

## 5. 方法调用的两种入口

```go
type Counter struct{ N int }

func (c *Counter) Inc() { c.N++ }

var c Counter
c.Inc()          // 编译期就知道跳到 Counter.Inc，可内联

var i interface{ Inc() } = &c
i.Inc()          // 查 itab，间接调用
```

值接收者方法，接口里存的是值的副本时，调用不会改到外面——和「方法集」规则一致。指针接收者要求接口里放指针，否则编译期就拒绝赋值。

---

## 6. nil 接收者 + 非 nil 接口

```go
type MyError struct{ Msg string }

func (e *MyError) Error() string {
	if e == nil {
		return "<nil>"
	}
	return e.Msg
}

var err error = (*MyError)(nil)
fmt.Println(err != nil)   // true
fmt.Println(err.Error())  // "<nil>" —— 方法能进来，接收者是 nil
```

接口非空，所以 `if err != nil` 会进分支；方法实现必须能扛 nil。标准库里不少 `Close` 这么写。

---

## 7. 对设计的启示

- 返回错误用 `return nil`，不要 `return typedNil`。
- 热路径避免把大量小对象反复装进 `any`。
- 接口适合边界；循环内部能具体就具体。
- 比较接口前确认动态类型可比较。
- `var _ I = (*T)(nil)` 既是编译期断言，也提醒你「nil 指针实现」是合法的。
