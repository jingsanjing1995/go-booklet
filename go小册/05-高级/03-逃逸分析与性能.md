# 03 · 逃逸分析与性能

性能工作的顺序应当是：**先正确，再测量，再改最热的那一段**。Go 里最常见的可优化点是**多余的堆分配**和**锁/系统调用太粗**。逃逸分析告诉你：编译器把变量放栈还是堆。

---

## 1. 看编译器的结论

```bash
go build -gcflags="-m" ./...
go build -gcflags="-m -m" ./...   # 更啰嗦
```

输出类似：

```text
./main.go:8:9: new(User) escapes to heap
./main.go:12:6: moved to heap: buf
./main.go:20:17: inlining call to fmt.Printf
```

「escapes to heap」= 生命周期超出栈，或被取址后流向未知位置。不是错误，只是成本：堆分配 + 未来 GC。

---

## 2. 常见逃逸原因

```go
func New() *User {
	u := User{Name: "Ada"}
	return &u // u 逃逸
}

func logIt(v any) {
	fmt.Println(v) // 装箱成接口，往往逃逸
}

func grow() []byte {
	s := make([]byte, 0, 32)
	// 若 s 被返回或容量在未知路径增长
	return s
}
```

典型触发：

- 返回局部变量指针
- 闭包捕获并逃出函数
- 赋给接口（`any`、`error` 接口装箱）
- 发给 channel
- 编译器无法证明不被外界引用
- 切片太大，栈上放不下（过大则直接堆）

反例：小结构体当值传递、循环里的局部 int，通常在栈上，零 GC 压力。

---

## 3. 减少分配的手法（测过再上）

**复用缓冲**

```go
var buf []byte
for _, item := range items {
	buf = buf[:0]
	buf = append(buf, item...)
	use(buf)
}
```

**strings.Builder / bytes.Buffer + Reset**，或 `sync.Pool`（高并发短生命周期对象）。

**避免 `fmt` 在热路径**

`fmt.Sprintf` 分配多。固定格式用 `strconv`、`AppendInt`。

**少用接口装箱**

```go
func id(n int) int { return n }          // 无装箱
func idAny(v any) any { return v }       // 有
```

热循环里 `for _, v := range s { sink(v) }` 若 `sink` 收 `any`，每个 v 都可能分配。

**切片预分配**

```go
out := make([]T, 0, len(in))
```

少几次 grow，少几次拷贝。

**指针 vs 值**

大结构体传指针少拷贝；极小结构体传值少堆分配。以 `-benchmem` 为准，不要教条。

## 4. 基准怎么写才不像骗自己

```go
func BenchmarkEncode(b *testing.B) {
	u := User{Name: "Ada"}
	b.ReportAllocs()
	b.ResetTimer()
	for i := 0; i < b.N; i++ {
		_, _ = json.Marshal(u)
	}
}
```

- 不要在循环里 `time.Now` 当数据源（自己变成热点）。
- 防止编译器消除：把结果赋给包级 `sink` 或 `_ =`。
- 比较时固定 `GOMAXPROCS`，关其它负载。
- pprof：

```bash
go test -bench=Encode -cpuprofile=cpu.pprof
go tool pprof -http=:0 cpu.pprof
go test -bench=Encode -memprofile=mem.pprof
```

生产：`net/http/pprof` 挂到内部端口，短时间 `curl` 采集。注意鉴权，不要暴露到公网。

## 5. 编译器还做了什么

- **内联**：小函数消失在调用点，`-gcflags="-m"` 会说 `inlining`。`//go:noinline` 仅调试用。
- **边界检查消除**：编译器证明下标安全时去掉 panic 检查。
- **PGO**（Profile-Guided Optimization，1.20+）：用线上 profile 指导内联和布局。

```bash
go build -pgo=default
```

先有真实 profile，再谈 PGO。

---

## 6. 优化清单（按性价比）

1. 算法和次数：少做无用功，批处理，缓存对的东西。
2. I/O：缓冲、复用连接、并发上限、避免 N+1 查询。
3. 分配：看 `allocs/op`，改热函数。
4. 锁：缩小临界区，读写分离要测。
5. GC：`GOMEMLIMIT`、减少存活垃圾、少用 Finalize。
6. 汇编 / cgo：最后 1%，且有维护成本。

没有 pprof 证据就改「感觉慢的地方」，是高级篇里最不高级的行为。
