# 01 · 泛型

Go 1.18 引入类型参数。目标不是把语言变成 C++ 模板展览，而是让「切片去重、map 取值、容器」不必再靠 `interface{}` 和复制粘贴。能用具体类型或接口表达的，仍然优先不用泛型。

---

## 1. 函数上的类型参数

```go
func Ptr[T any](v T) *T {
	return &v
}

func First[T any](s []T) (T, bool) {
	if len(s) == 0 {
		var zero T
		return zero, false
	}
	return s[0], true
}

n := Ptr(3)          // T = int
s, ok := First([]string{"a", "b"})
```

`any` 就是「没有任何约束」。需要运算时加上约束。

---

## 2. 约束：接口的第二种用法

```go
func Max[T ~int | ~int64 | ~float64](a, b T) T {
	if a > b {
		return a
	}
	return b
}
```

`~int` 表示「底层类型是 int 的类型」，于是 `type Age int` 也能进来。没有 `~` 时，只有真正的 `int`。

接口可以同时写方法和类型集合：

```go
type Number interface {
	~int | ~int32 | ~int64 | ~float64
	comparable // 可选：还得能 ==
}
```

`comparable` 是预声明约束：可以用 `==` 的类型。map 的键就需要它。

```go
func Keys[K comparable, V any](m map[K]V) []K {
	out := make([]K, 0, len(m))
	for k := range m {
		out = append(out, k)
	}
	return out
}
```

标准库 `cmp.Ordered`（1.21+）覆盖可排序的内建类型。`min`/`max` 内建函数很多时候已经够用。

## 3. 泛型类型

```go
type Set[T comparable] struct {
	m map[T]struct{}
}

func NewSet[T comparable]() *Set[T] {
	return &Set[T]{m: make(map[T]struct{})}
}

func (s *Set[T]) Add(v T) { s.m[v] = struct{}{} }

func (s *Set[T]) Has(v T) bool {
	_, ok := s.m[v]
	return ok
}
```

方法不能再声明自己的类型参数（目前语言限制）：

```go
// 非法
func (s *Set[T]) Map[U any](f func(T) U) *Set[U]
```

需要的话写成包级函数：`func MapSet[T comparable, U comparable](...)`。

---

## 4. 类型推断与显式指定

```go
First([]int{1})     // 推断 T=int
First[int](nil)     // 无法从 nil 推断，显式写
```

多个参数互相约束时，编译器从实参凑齐。凑不齐就写出来，不要和编译器打架。

---

## 5. 和接口怎么选

| 需求 | 选择 |
|------|------|
| 运行期多种类型、方法调用 | 接口 |
| 编译期同一算法套多种类型、要保留具体类型 | 泛型 |
| 只要能 `Read` | `io.Reader` |
| 切片里找最大值 | 泛型或 `slices.Max` |
| JSON 解码成未知结构 | `any` + 断言，或泛型 `Decode[T]` |

```go
func Decode[T any](r io.Reader) (T, error) {
	var v T
	err := json.NewDecoder(r).Decode(&v)
	return v, err
}
```

这比返回 `any` 好用得多。

---

## 6. 标准库已经泛型化的部分

- `slices`：`Contains` `Index` `Sort` `Clone` `Compact` `Delete` `BinarySearch`
- `maps`：`Clone` `Copy` `Keys`（旧版本在 x/exp）`Equal`
- `cmp`：`Compare` `Ordered` `Less`
- `sync/atomic`：`atomic.Pointer[T]`
- `net/http` 没有为了泛型改 Handler，接口仍然够用

写新代码先搜标准库，再自己造 `Map`/`Filter`。

---

## 7. 限制与品味

- 没有特化（对 `int` 写一套、对 `string` 再写一套更猛的实现）。
- 没有方法级额外类型参数。
- 约束目前不能表达「有某个字段」。
- 错误信息有时很长，把约束拆成命名接口会好读一些。
- **不要把所有函数都加上 `[T any]`**。三个具体函数比一个抽象到失去含义的泛型有价值。

性能：类型参数在编译期实例化，一般和手写具体类型接近。不要指望用接口装箱去「假装泛型」还更快——那是另一笔装箱开销。

对应示例：`codes/08-generic`。
