# 06 · 项目结构与工程实践

Go 不强制一种目录宗教。官方态度是：包按职责切，保持扁平，别过早模仿巨型单体的 `layers/controllers/services/repositories`。这一章给一套**小到中型服务够用**的骨架，以及日常工程习惯。

---

## 1. 推荐的中型骨架

```text
shop/
  go.mod
  README.md
  cmd/
    shopd/main.go          # 组装、信号、退出
    shopctl/main.go        # 可选 CLI
  internal/
    httpapi/               # HTTP 适配
    user/                  # 领域：类型、逻辑、存储接口
    user/memory.go         # 实现
    user/postgres.go
    config/                # 读环境变量
  testdata/
  Makefile 或 justfile     # 可选
```

原则：

- `cmd` 薄：只解析配置、构造依赖、Listen、等信号。
- 领域包不 import HTTP 细节。HTTP 层依赖领域，而不是反过来。
- 能放一个包就不要拆三个。`internal/user` 同时有逻辑和接口往往够了。
- 公开库才需要精心设计导入路径；私有服务大胆用 `internal`。

反模式：

```text
internal/controller
internal/service
internal/repository
internal/dto
internal/vo
internal/utils
```

每一层一个文件、方法只是转发，这是在用目录假装架构。等真的出现第二种入口（gRPC + 任务队列）再抽端口。

## 2. 配置

```go
type Config struct {
	Addr    string
	DSN     string
	Timeout time.Duration
}

func FromEnv() (Config, error) {
	c := Config{
		Addr:    getenv("ADDR", ":8080"),
		DSN:     os.Getenv("DSN"),
		Timeout: 5 * time.Second,
	}
	if c.DSN == "" {
		return Config{}, errors.New("DSN required")
	}
	return c, nil
}
```

12-factor：环境变量 + 合理默认。复杂项目可用一小段 YAML，但不要在运行时热加载十种来源却没有单一真源。密钥不要进仓库。

## 3. 依赖注入：手工就够

```go
func main() {
	cfg, err := config.FromEnv()
	if err != nil {
		slog.Error("config", "err", err)
		os.Exit(1)
	}
	repo, err := user.NewPostgres(cfg.DSN)
	if err != nil {
		slog.Error("db", "err", err)
		os.Exit(1)
	}
	svc := user.NewService(repo)
	h := httpapi.New(svc)
	// server...
}
```

Google 的 wire 等工具在超大仓库有用。中小项目，`main` 里十几行组装比魔法容器好查。

测试时对 `user.Repository` 接口塞假实现即可。

## 4. 日志、指标、追踪

- 日志：`slog`，带 `trace_id`（从 context 取）。
- 指标：请求数、延迟直方图、错误数。Prometheus 客户端很常见。
- 追踪：OpenTelemetry。先把 context 传下去，再挂 provider。

三者都不要在领域函数里直接打到全局再硬编码格式。传入 `*slog.Logger` 或从 ctx 取，测试才能安静。

## 5. 错误到 HTTP 的边界

领域返回 `error`（含哨兵/类型）。HTTP 层翻译：

| 领域 | HTTP |
|------|------|
| `ErrNotFound` | 404 |
| `ErrInvalid` | 400 |
| `ctx.Canceled` | 499 / 不告警 |
| `DeadlineExceeded` | 504 或 408 |
| 其它 | 500 + 日志 |

边界上做一次翻译，里面不要 `fmt.Errorf("404: ...")` 用字符串冒充协议。

## 6. 版本、发布、CI 清单

```bash
gofmt / goimports
go test -race ./...
go vet ./...
go build ./...
```

可选：`staticcheck`、`govulncheck`、golangci-lint（规则要团队共识，别一次开 200 个）。

构建：

```bash
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -X main.version=$VER" -o bin/shopd ./cmd/shopd
```

Docker：多阶段，最终镜像用 `scratch` 或 `distroless`，拷贝二进制和时区/证书。

## 7. 代码风格速记

- 格式化唯一：`gofmt`。
- 错误包一层：`fmt.Errorf("op: %w", err)`。
- 接口小，定义在使用方。
- 避免 `init` 连库。
- 避免全局可变状态；`http.DefaultClient` 那种要知道风险。
- 注释写「为什么」，类型和函数名写「是什么」。
- 导出谨慎。能不导出就不导出。

Effective Go、Go Code Review Comments、官方 Wiki 的 Go Proverbs（`Clear is better than clever`）值得读一遍。
