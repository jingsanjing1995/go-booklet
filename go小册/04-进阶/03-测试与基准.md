# 03 · 测试与基准

Go 把测试做成工具链的一部分：文件名、函数名、包 `testing`，没有第二套框架要学。写不好测试的并发和重构，都是在裸奔。

---

## 1. 最小测试

`greet.go`：

```go
package greet

func Hello(name string) string {
	if name == "" {
		return "hello, gopher"
	}
	return "hello, " + name
}
```

`greet_test.go`：

```go
package greet

import "testing"

func TestHello(t *testing.T) {
	got := Hello("Ada")
	want := "hello, Ada"
	if got != want {
		t.Fatalf("Hello(Ada) = %q, want %q", got, want)
	}
}
```

```bash
go test ./...
go test -v -run TestHello
go test -count=1 ./...   # 禁用缓存
```

`t.Fatal*` 立刻结束当前测试函数；`t.Error*` 记失败但继续。需要停就 Fatal，想多看几个断言用 Error，或用表驱动一次只测一组。

## 2. 表驱动

```go
func TestHello(t *testing.T) {
	tests := []struct {
		name string
		in   string
		want string
	}{
		{"named", "Ada", "hello, Ada"},
		{"empty", "", "hello, gopher"},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			t.Parallel()
			if got := Hello(tt.in); got != tt.want {
				t.Fatalf("got %q want %q", got, tt.want)
			}
		})
	}
}
```

`t.Run` 产生子测试，失败时名字会出现在输出里。`t.Parallel()` 让子测试并行；共享的可变状态必须先拷走。

## 3. 外部测试包与黄金文件

`package greet_test` 只能看到导出 API，适合当「用户文档」。

大段输出用 `testdata/`：

```go
func TestFormat(t *testing.T) {
	got := Format(input)
	want, err := os.ReadFile("testdata/format.golden")
	if err != nil {
		t.Fatal(err)
	}
	if string(got) != string(want) {
		t.Fatalf("mismatch\n got: %s\nwant: %s", got, want)
	}
}
```

用环境变量更新黄金文件（自己写个 `-update` flag）是常见手法，避免手改。

## 4. Helper、TempDir、Cleanup

```go
func setup(t *testing.T) *Server {
	t.Helper()
	dir := t.TempDir()
	s, err := Start(dir)
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { s.Close() })
	return s
}
```

- `t.Helper()`：失败行号指到调用方，而不是 setup 内部。
- `t.TempDir()`：测完自动删。
- `t.Cleanup`：比自己 `defer` 更适合子测试。

## 5. 基准

```go
func BenchmarkHello(b *testing.B) {
	for i := 0; i < b.N; i++ {
		_ = Hello("Ada")
	}
}
```

```bash
go test -bench=Hello -benchmem ./...
```

`b.N` 由框架调整到足够时间。不要在循环里做无关分配（或用 `b.ResetTimer()` 排除准备阶段）。

```go
func BenchmarkJoin(b *testing.B) {
	words := []string{"go", "xiao", "ce"}
	b.ReportAllocs()
	b.ResetTimer()
	for i := 0; i < b.N; i++ {
		_ = strings.Join(words, ",")
	}
}
```

比较优化前后：同一机器、关省电、多跑几次。数字波动 5% 内别太激动。

## 6. Fuzz（1.18+）

```go
func FuzzReverse(f *testing.F) {
	f.Add("Go小册")
	f.Fuzz(func(t *testing.T, s string) {
		got := ReverseRunes(ReverseRunes(s))
		if got != s {
			t.Fatalf("%q -> %q", s, got)
		}
	})
}
```

```bash
go test -fuzz=FuzzReverse -fuzztime=10s
```

失败输入会落进 `testdata/fuzz/...`，应提交进仓库，成为回归用例。对解析器、编解码特别值得。

## 7. 竞态、覆盖率、示例

```bash
go test -race ./...
go test -coverprofile=c.out ./...
go tool cover -func=c.out
```

示例函数会出现在 `go doc` 里，而且会被当测试跑：

```go
func ExampleHello() {
	fmt.Println(Hello("Ada"))
	// Output: hello, Ada
}
```

`Output:` 注释必须精确匹配 stdout。

---

## 8. 测试里的依赖

不要为了测 `FindUser` 起整个数据库，除非那是集成测试。常用手法：

- 小接口 + 假实现
- `net/http/httptest`（`httptest.NewServer` / `NewRecorder`）
- `testing/fstest`、`io.Pipe`
- 时间：传入 `func() time.Time` 或 `Clock` 接口，避免 `time.Now` 写死

集成测试可以用构建标签：

```go
//go:build integration

package shop_test
```

```bash
go test -tags=integration ./...
```

对应示例：`codes/10-test`。
